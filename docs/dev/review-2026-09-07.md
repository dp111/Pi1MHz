# Whole-tree review, 2026-09-07
## C. Beeb-visible hangs and poll-loop stalls

### C4. `fat_service.c` — unbounded FatFs/SD work in FIQ **[noted, not changed]**

`fat_service_command` runs from a `WRITE_FRED` callback and calls
`disk_read`/`f_read` inline; the per-command caps bound the *region*
(`sectors` up to the whole 32 MB disc RAM), not the transfer, so one command
can hold FIQ for ~2 s at the card's bulk rate.

**Disposition (2026-09-07): noted.** The service has always run the Beeb's
own synchronous requests in FIQ - that is its design, stated in its header
comment, and the Beeb-side filing system is blocked waiting on the very
transfer it asked for, so a long command is a long *request*, not a hang.
The Pi side is what pays: no other bus cycle and no poll-loop work during the
transfer.  Bounding a single command would only push a bulk load into several
commands with the same aggregate cost.  The genuine fix is the
latch-and-defer shape the SCSI juke, AUN and net services use (FIQ latches,
the main loop services), which is the CLAUDE.md rule for SD work - a
restructure of the service's command model, and the owner's call.  Left open
for that decision.

## F. Layering

### F1. `BeebSCSI/scsi.c:1156, 745, 1509` — VFS writes are refused with CHECK CONDITION and skip their data-out phase

The code is deliberate and carries its rationale:

```c
/* VFS write-protect: LUN >= 8 is read-only LaserDisc media and the VFS
   ROM never issues WRITE6 ... Refuse at command phase - a tripwire for
   any unexpected writer. */
```

but it contradicts the rule in CLAUDE.md — *"Beeb writes are silently
accepted-and-discarded — never refused with an error, because the Beeb's FS
handshake loops have no timeouts"* — and the filesystem layer contradicts itself
on the same point: `filesystem.c:943-947` states the rule, `filesystemWriteNextSector`
obeys it, while `filesystemWriteAttributes:1203`, `filesystemFormatLun:1240` and
`filesystemOpenLunForWrite:1644` all return false for LUN ≥ 8.

Because the refusal is placed *before* `ITPHASE_DATAOUT`, a writer that does reach
it is left waiting on REQ mid-transfer rather than getting a clean error.

**This is a decision, not a defect — it needs the owner's call**: keep the
tripwire (and accept the rule's exception, ideally written down), or run the data
phase, discard the bytes and return GOOD.

## G. Duplication

### G2. `wifi/sdio.c` — blocking bring-up functions duplicated by the stepped ones **[noted; the destructive probe is gated off]**

**Disposition (2026-09-07): noted.** `nm` on the release ELF shows LTO already
discards every probe-only `sdio_probe_*` function: only `sdio_probe_read_byte`,
`_write_byte`, `_read_function2_registers` and
`_send_single_tx_control_template_timeout` survive, all shared with the
runtime path, plus `g_sdio_probe_result` (its TX template is live).  So the
five blocking copies cost nothing in the image; retiring them is source
tidiness, and the owner ruled it must not be done mechanically.  Left for a
deliberate pass with a usage map.

### G3. Three copies of the glyph rasteriser **[noted]**

**Disposition (2026-09-07): noted.** `fonts.c` paints fg+bg through the font
vtable; `primitives.c`'s VDU 5 path paints foreground only and cannot use
`write_char(fg, bg)` without a transparent-background mode; `teletext.c`
doubles the height; `videoplayer.c` uses its own font.  Unifying them is a
layering redesign (a font-supplied `write_char` would need to serve all
four), not a dedup.

### G7. Three hand-rolled dotted-quad IPv4 parsers **[noted, not changed]**

`teletext_emulator.c` (`ttx_parse_endpoint`), `AUN/aun_config.c` (`parse_ip`),
`wifi/wifi.c` (`wifi_parse_ipv4`) — with lwIP's `ipaddr_aton` already linked.

**Disposition (2026-09-07): noted.** The three have different contracts, not
one: the AUN parser advances a cursor inside the `net.stn=a.b.c.d` map
grammar, the teletext one parses `host:port`, and the WiFi one validates and
copies the text into the config block as well as the octets.  lwIP's
`ipaddr_aton` is BSD `inet_aton`: it accepts `"1"`, `"1.2"`, hex and octal
octets, so swapping it in would loosen what the config files accept.  A
shared strict parser would be a fourth function serving three call sites.
Not worth the churn.

### G8a. Two case-insensitive leftovers **[noted]**

`ws_hex_eq_ci` is a constant-time compare for the Digest response and must
not become a `strncasecmp`; `ws_hexval` / `sdio_hex_nibble` are the same
four-line function in two subsystems with no shared home worth creating.

### G9. Two small pairs left as they are **[noted]**

`filesystemVFSVolumePresent` (cached) and `filesystemVFSDatPresent` (one
uncached stat) sit on the READ6 path and are deliberately cheaper than the
type probe's second stat when the file is absent; the webserver and MTP FAT
date packers differ in syntax and each is one function in its own module.

## H. Dead code — what remains **[noted, owner's decisions]**


- `rpi/mailbox.c` — no bound on `RPI_PropertyAdd`: every request starts
  from index 2 and the largest fixed sequence is 12 words against 8192;
  nothing passes a data-dependent count (owner's decision).
- `rpi/cache.c:145-152, :439` — the missing DSB before the SCTLR.C clear and
  the TTBR0 shareability mismatch are CP15 changes: kernel7/A53 needs a
  hardware boot test for either, and A53 chain-boot is currently broken.
- `rpi/sdcard.c:1545, :1312/1488, :1050-1096` — CMD12 recovery dropping the
  4-bit bus, the partial-init `card_rca` gate and the three stacked timeouts
  all need a faulting-card rig to test; "SCSI/SD is reliable" is the owner's
  verdict, so these are theirs to schedule.
- `BeebSCSI/cpuspecific.h` `cli()`/`sei()` — vestigial AVR pairs; cosmetic.
- `fcode.c:86-108` — the deferred-acknowledgement slot has no queue; a
  protocol design question.
- `framebuffer/fonts.h:34-44` — `char` metrics differ in signedness between
  ARM and the x86 conformance host; the right fix is `uint8_t` across the
  font API, best done with the vdutest oracle running.
- `framebuffer/primitives.c:446-451, 582-587` — ellipse coefficient overflow
  near 1300 px belongs with the ellipse recurrence work.
- `framebuffer/framebuffer.c:1500-1533` — the "eight identical case bodies"
  were not at those lines after today's edits; re-locate before acting.
- `framebuffer/screen_modes.c:905, 989` — CLS/scroll through `set_pixel`
  rather than `fill_hline`: a performance change, to be validated with the
  vdutest differential harness.
- `framebuffer/primitives.c:1092-1106` — a deterministic abandon on flood
  queue wrap changes PLOT 133's output; owner's call.
- `AUN/aun.c:1111-1114` — learn-mode eviction is an opt-in feature design.
- `rpi/auxuart.c:99-103` — a dead VideoCore gives no core clock to derive a
  baud divisor from; there is no correct fallback.
- `rpi/screen.c:398-407` — a format check inside `plane_write_fields` could
  silently drop a write; both callers already discriminate.
- `framebuffer.c:1404, 1240` vs `:1971` — `vdu_enqueue` reserving position as
  well as space is a queue redesign.
- `wifi/webserver.c:4768, 4756` — `dav_put_flush` discards `ws_error`'s
  return; its two direct callers return immediately, so making this safe
  needs a trace of every path above them, not a local change.
- `teletext_emulator.c:394-403` — the field copy itself stays unmasked
  (holding FIQ off for a kilobyte of memcpy is a timing decision); the
  pointer pair is masked.
