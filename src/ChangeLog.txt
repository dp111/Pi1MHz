v.1.31
Beeb_write_protect config option: ignore all writes from the Beeb to the SD card (MMFS/MMFS2 and ADFS), while USB and web/WebDAV access stay read-write.
AUN Fix * notify etc
Add a web browser for viewing/modifying .ssd .dsd .mmb files scsi.dat can only be viewed.
Update 43455 WiFi firmware to 7.45.265 (Pi 3B+/4/CM4).
Hardware H264 video player for the Domesday LaserDisc emulation (needs the full start.elf, gpu_mem=64 and vd_use_vpu0=1).
Removed the frame.lz still-frame background, its LZ4 decompressor and the 4:2:2 YUV plane - superseded by the video player.
Audio rework: one audio core (int16 ring) shared by Music 5000, BeebSID and the video player; Beeb pin always carries the proper mono mix; Audio_out=hdmi plays over HDMI (direct MAI, no firmware service).
Video player: video.pvf lives in /BeebVFSn next to the volume, follows the VFS jukebox, and reopens on remount; stills/steps fixed after the first; VP415 speed F-codes (SxxxF/SxxxS, U/V/W/Z), X, and the D0/D1 picture number display.
Audio no longer clicks during disc activity: transfers keep the DMA fed and the player rides out SD latency spikes.
Web /status: audio, video player, SD throughput and per-poll timing diagnostics; /audio.wav returns the last third of a second of sound; PUT size limit raised to 4GB for video uploads.
Disc menu support: ?T / ?Y F-codes return the mounted VFS disc's Title/Description from its scsi0.cfg (read the reply with OSWORD &62 cmd &C8); a Domesday-style menu disc for /BeebVFS0 is built by tools/make_vfs_menu.py.
Framebuffer: a mode change now resets the font scale/spacing - the boot splash's double-width font no longer leaks into the Beeb's screen modes (everything rendered 20 columns wide after a reset).
Web /status "Bus diag" row (debug builds only): SCSI bus event counters, engine state and the last command block. Release builds carry no SCSI diagnostic instrumentation - the FIQ event counters and command capture compile away.
Fixed a byte-level race between the SCSI data port (written from FIQ) and the status register (written from the main loop) sharing one VPU memory word: a lost update corrupted transfers (ADFS Bad sum/Bad FS map after a BREAK) or left a stale busy status that hung VFS until another BREAK. Byte writes to the shared window are now atomic.
WiFi no longer stays dead until a BREAK when a runtime chip restart fails bring-up: the error state now retries the full init on a doubling backoff (1-10 minutes) instead of stopping permanently.
Fixed the Pi dying (and the Beeb wedging against the dead bus) at BREAK: the video player used to open video.pvf, start the hardware decoder and decode picture 1 at every boot and every BBC reset, so an SD stall inside its poll tripped the 10 s watchdog mid-reset. The player now brings nothing up until the first player F-code arrives; a Beeb reset does no video file or GPU work at all.
Lockup forensics on /status: a CPU fault or watchdog death now reports where it happened on the next boot ("previous boot died at stage/init/poll callback ..."), from a record that survives the reset. The SD data-FIFO wait is also bounded by wall clock so a failing card errors out instead of hanging into the watchdog.
SD reliability: FatFs no longer trusts the card's FSINFO sector (stale free-count/next-free hints caused phantom free-space readings and failing large writes); a WebDAV PUT whose file is revoked or fails mid-transfer now errors instead of returning success for a truncated upload.
A video-only overlay mode selected with no video open (a data-only disc side) now shows black instead of a stale frame buffer: the video plane is only enabled once the player has a real frame.
Eject = disc flip: the VP415 eject F-code (') and a SCSI START/STOP with the eject bit now swap a VFS LUN to its partner side's directory (odd <-> even, 1<->2, 3<->4 ...), so AIV software asking for the disc to be turned over gets the other side. F-code ,1 (load) acknowledges ready.
VP415 overlay modes 4 (Mixed) and 5 (Enhanced) now display hard-keyed (both planes visible) instead of doing nothing; VPX reports the selected mode. F-code : (reset to defaults) clears the player state.
VFS volumes are write-protected: LUN >= 8 images are never created, formatted or written - an ADFS-style format aimed at a VFS drive is silently accepted and discarded (never an error, which would hang the Beeb's no-timeout handshake loops).
The menu disc's MENU is now a tokenised BASIC program CHAINed by !BOOT (tools/bbc_tokenise.py, round-trip verified) - boot is near-instant instead of *EXECing a 9K listing. The menu pointer supports the AMX mouse as well as the RB2 trackerball (P toggles the decode).
Disc menu v2: scans /BeebVFS0-49, lists only installed discs (paginated), and drives video-only discs (a video.pvf with no scsi0.dat) with a built-in player - play/still/step/slow/fast/goto and audio/picture-number toggles over the F-codes. A scsi0.cfg names a video-only disc in the menu.
